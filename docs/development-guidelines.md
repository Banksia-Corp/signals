# Development & Contributor Guidelines

This document outlines core architectural principles, development lifecycles, and quality gates for contributors and AI agents working on `@banksia/signals`.

---

## 1. Core Architectural Principles

When contributing to `@banksia/signals`, you must preserve its foundational design invariants:

### Zero Runtime Dependencies in Core

- The core reactivity engine (`@banksia/signals`) has **zero external runtime dependencies**.
- Core utilities must rely purely on native TypeScript / JavaScript constructs (ES6 `Proxy`, `Reflect`, `WeakMap`, `Set`, `Map`, `queueMicrotask`).

### Optional Peer Dependencies for Framework Adapters

- Framework integrations (`@banksia/signals/react`, `@banksia/signals/lit`, `@banksia/signals/solid`) must treat UI frameworks purely as **optional peer dependencies**.
- Importing `@banksia/signals` must never require or bundle React, Lit, or SolidJS.
- Framework adapters must properly handle framework lifecycle teardown to prevent unmounted component leaks.

### Fine-Grained Reactivity Guarantees

- **Identity Preservation**: `makeReactive(obj)` on an already-reactive proxy returns the same proxy instance; `toRaw(proxy)` always extracts the original raw target.
- **Microtask Batching**: Multiple mutations within synchronous blocks or methods should automatically coalesce into a single reaction turn via `queueMicrotask` / `batch()`.
- **Targeted Collection Invalidation**: Array, Map, and Set operations must only trigger reactions for affected indices, keys, sizes, and iteration iterators.
- **Subscription Lifecycle & Leak Prevention**:
  - `computed` signals are lazy and memoized, only computing when read and invalidating dependents when their upstream signals change.
  - `effect` cleanup functions must be executed before subsequent re-evaluations and during teardown.
  - Circular dependency chains should be safely guarded against infinite recursion.

## 2. Development Lifecycle & Quality Gates

Every modification—whether human-authored or generated by an AI coding agent—must pass all quality gates locally before being committed or merged.

### Required Pre-Submission Verification

```bash
# 1. Run full unit and integration test suite
pnpm run test

# 2. Check formatting and code style across all source files and docs
pnpm run lint

# 3. Verify bundle builds cleanly via Rslib
pnpm run build
```

### Code Formatting with Prettier

We enforce consistent formatting with Prettier across TypeScript source files, tests, and markdown documentation:

```bash
# Automatically format all files in the workspace
pnpm run format
```

## 3. Subpath Exports & Public API Contracts

`@banksia/signals` exposes explicit subpaths in `package.json`. Any architectural changes must maintain type declarations and export contracts:

| Subpath                         | Description                          | Key Primitives                                                                                                                                            |
| :------------------------------ | :----------------------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`@banksia/signals`**          | Core engine & low-level telemetry    | `makeReactive`, `isReactive`, `toRaw`, `signal`, `computed`, `effect`, `batch`, `flushBatch`, `registerReactivityHooks`, `observe`, `createReactivityHub` |
| **`@banksia/signals/react`**    | React 18/19 hooks & HOCs             | `useReactive`, `observer`, `useSignal`, `useComputed`                                                                                                     |
| **`@banksia/signals/lit`**      | Lit element controller               | `SignalsController`                                                                                                                                       |
| **`@banksia/signals/solid`**    | SolidJS fine-grained accessor bridge | `createSolidSignalBridge`                                                                                                                                 |
| **`@banksia/signals/vanilla`**  | Zero-framework DOM bindings          | `bindDOM`, `bindText`                                                                                                                                     |
| **`@banksia/signals/devtools`** | DevTools runtime & MCP bridge        | `initDevTools`, `connectDevTools`, `disconnectDevTools`, `getDevToolsBridge`, `DevToolsBridge`                                                            |

### Documentation Integrity

- Whenever public APIs, subpath exports, or framework integrations are modified or added, update both [`README.md`](../README.md) and [`AGENTS.md`](../AGENTS.md).
- Keep API matrix tables and code examples accurate and functional.
